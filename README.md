# 县域农产品直播带货选品质检发货售后平台

以**商品批次**为主线的全链路平台：农户/合作社提交水果、米面、菌菇、蜂蜜、腊味等农产品 → 运营选品质检（样品试吃）→ 直播排期（上架前履约检查）→ 仓库锁库锁包材 → 直播下单自动生成分温区发货任务 → 售后工单 → 农户结算 → 县域运营复盘。售后结论反向回流到下一场的选品、主播口径、预售量与县域公共品牌公告。

## 技术栈

- **前端**：Vue 3 + Vite + Element Plus + Pinia + Vue Router + ECharts
- **后端**：NestJS 10 + TypeORM（JWT 认证 + 角色权限）
- **数据库**：PostgreSQL 15（首次启动自动建表并写入演示种子数据）

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

| 服务 | 地址 |
|---|---|
| 前端（nginx） | http://localhost:8080 |
| 后端 API | http://localhost:3000/api |
| PostgreSQL | localhost:5432（postgres/postgres，库 agri_live） |

后端首次启动时自动同步表结构并写入种子数据（7 商品 / 7 批次 / 5 场直播 / 550 笔订单 / 33 张售后工单 / 坏果预警·质检复盘 / 风险事件与结算单），无需手动初始化。

> 出库照片、到货照片、用户拍照证据为内置演示 SVG，由后端静态托管在 `/api/evidence/*.svg`（容器内 `backend/evidence`），经 `/api` 反代直接在页面预览。

## 本地开发

```bash
# 1. 数据库（任选其一）
docker run -d --name pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=agri_live -p 5432:5432 postgres:15-alpine
# 或使用本机已有 PostgreSQL，创建数据库 agri_live

# 2. 后端（默认连 localhost:5432，可用 DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME 覆盖）
cd backend && npm install && npm run build && npm start   # http://localhost:3000

# 3. 前端（vite 已配置 /api 代理到 3000）
cd frontend && npm install && npm run dev                 # http://localhost:5173
```

## 核心页面与业务闭环

1. **商品与批次**（农户）：填写产地、采摘时间、规格、库存、检测报告及有效期、保质期、冷链温区、包装耐压、可供直播批次；运营在此审核商品。
2. **选品质检**（运营）：对待选批次做样品试吃评分（1-10）与质检决策，通过即 `qc_passed`。
3. **直播排期**（运营）：选批次时自动弹出**上架前履约检查**——样品口感、检测报告有效期、采摘窗口、保质期覆盖、包装耐压、冷链可达城市、农户交货稳定性、可供库存八项对照，给出建议预售上限；创建场次含主播、脚本、承诺口径、价格、优惠券、预计销量。
4. **库存锁定**（仓储）：按直播排期锁定库存与包材（县域中心仓/前置仓），可释放。
5. **直播执行**：开播 → 模拟下单（订单自动扣库存、超预估即触发 `oversell` 风险）→ 每单自动生成发货任务（订单+批次+发货仓+物流温区+随单承诺）。
6. **发货任务**（仓储）：发货/送达/异常；冷链任务可上报**冷链车晚到**，自动生成链路风险。
7. **售后工单**（售后）：坏果、少发、物流延误、地址错误、用户拒收、口味不符六类；坏果工单需登记**坏果表象**（压伤软烂/磕碰伤/过熟软烂/霉变/冻伤/脱水发皱）与**用户拍照证据**，系统快照该单包装方式、物流线路、到货城市温度、温区；处理后自动重算批次坏果率，超 5% 形成**坏果预警**；处理后可发起**反向决策**。
8. **坏果预警中心**（运营/售后/仓储，本题新增）：
   - **五维归因**：按采摘批次、**包装方式、物流线路、到货城市温度（含温区/运输峰值）、用户拍照证据**聚合，并用坏果表象给出责任倾向（压伤/磕碰→包装承压；过熟软烂→采摘成熟度过高；霉变/冻伤→温区）。
   - **自动冻结**：预警形成即冻结同批次剩余库存（可售库存 + 锁库未消耗），冻结批次**禁止下单、禁止发货**，并生成 `defect_alert` 风险事件。
   - **客服优先**：自动标记并列出命中**同城市 / 同线路 / 同包装**的待处理坏果工单，以及同线路/同高温城市已送达未报坏果客户的**主动回访名单**。
   - **质检复盘定责**：比对**出库照片、到货照片与物流温区**，可多次记录复盘；最终判定：①**包装承压**→必填"更换包装"，后续发货自动采用新包装、剩余库存解冻放行、赔付由平台承担不扣农户；②**农户采摘成熟度过高**→坏果赔付计入农户承担，**结算时扣款**，库存维持冻结；③**物流温区异常**→平台/物流承担；④**多方责任**→按比例分摊；⑤证据不足→解冻。
9. **农户结算**：直播结束后按 `供货价 × 销量 − 扣减` 生成结算单，坏果赔付按质检定责拆分为**农户扣赔（farmerBorneDeduction）与平台承担（platformBorne）**，运营打款。
10. **风险中心**：超预估、少供、报告过期、冷链晚到、坏果率升高、**坏果预警·库存冻结**、承诺不符等事件的知晓/处置；支持一键扫描检测报告过期批次。
11. **批次链路**：任一批次的时间线视图，串起选品→直播→锁库→订单→发货→**坏果预警/冻结/质检定责**→售后→结算→风险→反向决策。
12. **复盘分析**（运营）：农户稳定性评级、品类适合直播指数、售后原因分布、售后对复购率的影响。

## 异常场景演示（种子数据已内置）

- 批次 `B20261005-ST-01`（**高山奶油草莓**，本题新增）：发出 80 盒后 8 笔坏果赔付集中出现（坏果率 10%），已形成坏果预警 `DA2026100601` 并**冻结剩余库存 120 盒（80 可售 + 40 锁库未消耗）**；5 单"过熟软烂"集中在上海 30.4℃/宁波 29.9℃ 高温城市、3 单"压伤软烂"集中在杭州同冷链线路/普通泡沫托；已预置 1 条出库/到货照片+温区复盘（结论待定），2 张同城市/同线路/同包装待处理工单已入**客服优先队列**。登录后可在「坏果预警」走完质检定责 → 换包装 / 农户扣款全流程。
- 批次 `B20260920-AP-01`：销量 260 超预估 200（oversell）+ 坏果率 5.4%（14 张已解决坏果工单带压伤/磕碰拍照证据）+ 冷链晚到 2 单；**再处理 1 张坏果工单（坏果率超 5%）即自动形成坏果预警并冻结 240 件剩余库存**。
- 批次 `B20260910-LA-01`：检测报告 2026-10-03 已过期（report_expired）+ 主播承诺「纯手工无添加」与实际配料不符（promise_mismatch）→ 已生成品牌风险公告与「暂停该农户排播」决策
- 批次 `B20260928-KW-01`：直播中，农户预警连续降雨将少供（undersupply）

## 验证方式（本题实际执行过的验证）

在本地环境（Node 22 + PostgreSQL 15，临时实例 127.0.0.1:5433）实际执行并通过：

1. **构建**：`backend: tsc 编译通过`；`frontend: vite build 通过`（新增 `DefectAlerts` 视图 23KB）。
2. **种子启动**：后端启动自动建表并写入 7 商品/7 批次/5 场直播/550 订单/33 工单；`GET /api/analytics/overview` 返回 `frozenBatches=1、openDefectAlerts=1`。
3. **坏果预警五维分析**（`GET /api/defect-alerts/1`）：过熟软烂 5 单 / 压伤软烂 3 单；责任倾向 ripeness；用户拍照证据 8 份；包装维度含"普通泡沫托"；城市维度均带到货温度；命中城市收敛为上海/宁波/杭州；出库/到货照片任务 30 个。
4. **客服优先**（`GET /api/defect-alerts/1/priority`）：2 张待处理坏果工单命中同城市/同线路/同包装优先队列；主动回访名单 17 人。
5. **成熟度定责 → 结算扣款**：提交质检复盘后定责 `ripeness`，预警转"已定责"、`farmerDeduction=160`、库存维持冻结；`POST /api/settlements/generate/5` 生成草莓结算单：应收 1440 − **农户扣赔 160（平台承担 0）** = 实付 1280；随后闭环成功。
6. **包装定责 → 换包装解冻**：对猕猴桃批次人工立项冻结；冻结时发货、下单均被 400 拦截；缺"更换包装"参数被拒；定责 `packaging` + 更换为"加厚瓦楞纸箱+硬塑托"后自动闭环、库存解冻；解冻后新订单成功，自动生成的发货任务**采用新包装**并带物流线路与到货城市温度（南京 27.4℃）。
7. **自动触发链路**：对苹果批次新建并处理 1 张坏果工单（带表象+拍照证据，工单自动快照包装/线路/温度 24.2℃），系统自动形成坏果预警（坏果率 6%）、冻结 240 件剩余库存、风险中心出现 `defect_alert` 事件。
8. **证据图静态托管**：`GET /api/evidence/user-overripe.svg` 返回 200 且为 SVG。

> 说明：本工作区无 Docker 守护进程，Compose 配置按标准多阶段构建编写（backend: node20 构建+tsc 编译并内置 evidence 静态图；frontend: node20 构建+nginx 托管并反代 /api），与本地验证通过的构建/启动命令一致。
